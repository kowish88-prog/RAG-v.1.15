# Прототип RAG-ассистента для ответов на вопросы по тематике ИИ
Универсальный RAG-Q&A с гибридным поиском (FAISS + BM25), свежестью и взвешиванием источников, Gradio-интерфейсом, опциональной генерацией ответа через LLM (OpenAI-совместимые или HF Inference), а также **отдельным индексом “пула источников про ИИ”** с прогресс-индикацией и ручным добавлением URL.

---

## ✨ Возможности

- Гибридный ретривал: эмбеддинги (FAISS) + BM25 с нормировкой, взвешиванием надежности доменов и бустом свежести.
- Веб-добор по клику: опция «Дополнить инфо из Интернета» подкачивает страницы через DuckDuckGo + trafilatura.
- Пул источников про ИИ (отдельный индекс):
  - Кнопка «Собрать пул про ИИ» (stream-прогресс в UI).
  - Чекбокс «Только на основе пула про ИИ» — отвечать строго из этого пула.
  - Кнопка «Добавить URL» — пополнить пул вручную списком ссылок.
- Мои документы: загрузка PDF/DOCX/TXT/MD/HTML и отдельный индекс по вашим файлам.
- LLM по желанию: переключаемый провайдер — none (строгий режим), openai_compatible (через langchain-openai) или hf_inference (через HuggingFaceEndpoint).
- Экспорт: отчёт в DOCX и ZIP с HTML-копиями использованных источников.
- Безопасные цитаты: короткие выдержки по запросу без обрыва слов и предложений.

---

## 🧱 Архитектура

```
Вопрос ─▶ Санитайзер ─▶ (опц.) Веб‑обогащение ─▶ Индексы: FAISS + BM25
                                    │
                                    └── Блок‑лист доменов, таймауты

FAISS/BM25 топ‑чанки ─▶ (опц.) LLM (OpenAI/HF) ─▶ Форматированный ответ с цитатами и источниками
                                   │
                                   └── Строгий режим без LLM (только цитаты)

Экспорт: DOCX отчёт, ZIP источников

- **FAISS** — плотный поиск по эмбеддингам (`intfloat/multilingual-e5-small`, fallback на `paraphrase-multilingual-MiniLM-L12-v2`).
- **BM25** — разрежённый поиск со своей нормировкой и объединением с FAISS.
- **Recency boost** — свежие документы получают повышающий коэффициент.
- **Source weighting** — надёжные домены получают больший вес; есть **блок‑лист** (rutube, vk, ok, tiktok, x/twitter, youtube и т. д.).
- **Пул про ИИ** — отдельный индекс + кэш (`AI_CACHE`), ручное добавление URL, кнопка «Собрать пул про ИИ».
```

## Запуск

Сохраните код в `app.py` и выполните:

```bash
python app.py
```

Gradio выдаст локальный URL. В интерфейсе:
1) при необходимости откройте **⚙️ Настройки LLM** и выберите провайдера:
   - `none` — строгий режим без LLM (по умолчанию);
   - `openai_compatible` — требуется `OPENAI_API_KEY` и, при необходимости, `OPENAI_BASE_URL`;
   - `hf_inference` — требуется `HUGGINGFACEHUB_API_TOKEN` и `repo_id` модели.
2) задайте вопрос, настройте флаги (веб‑добор / только мои доки / только пул ИИ), нажмите **Отправить**.

## ⚙️ Элементы UI
- ✅ **Дополнить инфо из Интернета** — разовый веб‑добор в базовый индекс (DuckDuckGo + `trafilatura`).  
- ✅ **Только на основе пула про ИИ** — искать **только** в отдельном AI‑индексе.  
- ✅ **Отвечать только по моим документам** — поиск исключительно в пользовательском индексе (загрузка PDF/DOCX/TXT/MD/HTML).  
- ✅ **Собрать пул про ИИ** — стрим‑индикация прогресса сборки.  
- ✅ **Добавить URL** — вручную добавить ссылки в пул про ИИ.  
- ✅ **Top‑K** — сколько чанков попадёт в ответ.
- ✅ **Вес свежести (λ)** — усиливает свежие источники.
- ✅ **Макс. возраст (мес)** — отсечь старые источники.
- ✅ **Порог релевантности** — снизьте, если отклик пустой.
- ✅ **⏹️ Стоп** — прерывание долгого запроса.
- ✅ **🧽 Очистить чат** — сброс диалога.
- ✅ **Скачать отчёт (.docx)** — экспорт диалога.
- ✅ **Скачать источники (ZIP)** — HTML страниц, использованных в ответе.

## Конфигурация LLM

В UI задаются:
- **LLM провайдер:** `none` | `openai_compatible` | `hf_inference`  
- **Модель / repo_id:** напр. `gpt-4o-mini` или `HuggingFaceH4/zephyr-7b-beta`  
- **API Key / Base URL / HF Token** — в зависимости от выбранного провайдера

Поведение:
- `none` — генерация LLM выключена → краткие тезисы и цитаты **только** из источников.
- `openai_compatible` — используется `langchain_openai.ChatOpenAI` (совместимые эндпоинты: OpenAI/OpenRouter и др.).
- `hf_inference` — используется `HuggingFaceEndpoint` c задачей `text-generation`.
